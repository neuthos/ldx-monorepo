# Ringi 100 Cancellation Phase 3 — Test Plan

**Source spec:** `docs/ringi/specs/100-phase3-spec.md` (sync `r100p3-h47k29` with the TDD sheet).
**Consumers:** FE, BE, and E2E teams working in parallel. Technical register throughout.

## 1. Summary

### TL;DR
37 test cases cover all 29 Approved FRs of the four cancellation domains (Arrival, Shipment, Store Sales, Store Sales Return) plus the shared UX contract and authority model. Out of scope by human decision: the four batch-registration-upload FRs (FR-03/09/15/19 — rejected: separate cancellation batch-registration screens as phase 1/2). One BOUNDARIES letter is Partially covered (R — explicit double-confirm TC still to add).

### Coverage and confidence
- FR coverage: 29/29 Approved FRs (100 percent). Rejected FRs excluded and noted. No Question FRs remain.
- Confidence: 85 percent (estimated) — requirement traceability 1:1 with the sheet; BOUNDARIES walked with one partial; blast radius (cascades, EC, authority, phase-1 alignment) traced; evidence from the session's graph exploration of feat/ringi-100-cancellation BE and phase-2 FE components.

### Healthy pyramid
- Target: Unit ~70 / Integration 15-20 / E2E 5-10 (percent, by rows).
- Actual (by rows): Unit 15/37 (40), Integration 10/37 (27), E2E 12/37 (32) percent.
- Assessment: risk-adjusted deviation — the four PRD scenario suites are journey-shaped; each E2E row consolidates 3-8 PRD sub-scenarios. Sheet rows and this table are 1:1 (same TC-IDs and counts).

### BOUNDARIES summary
- B Covered (TC-04, 05, 16) — reason gating, closing boundary, quantity precision.
- O Covered (TC-03, 33) — re-entry, mixed STS/RST skip rules.
- U Covered (TC-04, 35) — multibyte remarks; Cancelled label localization.
- N Covered (TC-01, 04) — status tri-state; blank vs required details.
- D Covered (TC-33) — batch selection volume (upload FRs rejected).
- A Covered (TC-22, 37) — endpoint permissions; four authority levels.
- R Partially covered (TC-24) — chain savepoint/loop-safety only; explicit double-confirm TC pending.
- I Covered (TC-25, 10) — phase-1 path alignment; external-origin guard.
- E Covered (TC-28, 31, 35) — timezone-aware download dates; locale labels.
- S Covered (TC-02, 03, 05) — lifecycle, release, closing freeze.

### Blast radius
Cascades to Sales/Purchase chains (TC-20, 23), EC order/return (TC-20, 21), Customer Order re-enable (TC-19, 31), order.master outstanding + lots (TC-16), phase-1 regression incl. the approved _cancel_store_sales alignment (TC-25), authority masters (TC-22, 37).

### Assumptions
- Closing-date field for pickings pinned at implementation (candidates scheduled_date / date_done); store.sales uses sales_date (verified).
- E2E page objects follow the phase-1/2 CancellationBatchRegistration pattern (pages/inventory-control/...).

## 2. Data Preparation Summary
- Slips per domain (stock.picking arrival/shipment; store.sales STS/RSTS): Confirmed clean, Waiting/Draft, Pending Cancellation, Cancellation Confirmed, wrong-type variants, closing-locked (period closed via change.lock.date.history).
- Link fixtures: Paid/unpaid/draft Purchase on arrivals; billing-confirmed and billing-draft Sales on shipments; movement pair (inter.store.movement) done+done and done+waiting; Customer Order with shipment created; RSTS draft/confirmed; EC order/return confirmed; Sales with/without Sales Return.
- Blocker fixtures (Store Sales): point payment, granted points, coupon usage, tax-free process, Smaregi/POSCM/TeamStore origin flags, POS/daily-closed links; a receipt-issued cash slip (must still cancel).
- Actors: Read / Write / Approve / Write+Approve per cancellation item; guest.
- Baselines: stock free/reserved/total, lots (consumed/unconsumed), order.master outstanding, movement history rows.
