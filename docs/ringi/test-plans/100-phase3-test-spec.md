## 1. Summary

### TL;DR

Test plan for extending the governed two-step slip cancellation (Confirmed → 取消待ち → 取消確定) to four new slip types by replicating the approved phase 1/2 architecture. Highest risks: (1) cross-domain cascade correctness with full-chain reuse (Store Sales → Sales → Purchase; Arrival → Shipment movement pair), (2) inventory/lot/outstanding reversal side effects, (3) batch atomicity vs partial success, (4) regression of the already-approved phase 1/2 cancellation suites. All product decisions resolved (the Store Sales Information list label was decided as "Cancelled" per PRD-StoreSales 2.6). The plan is ready.

### Coverage and confidence

- BR/FR coverage: 20/20 requirement groups (100%), traced via the spec's `PRD-<doc> <section>#<no>` scheme (the PRDs carry section numbers, not formal FR/BR IDs — scheme defined in the spec).
- Test-plan confidence: 86% (estimated, not execution evidence).
- Confidence rubric: requirement traceability 40% → 36 (1:1 table traceability, all 20 groups covered); BOUNDARIES evaluation 20% → 17 (all ten addressed; E partially covered, justified below); blast-radius/domain-effect coverage 20% → 18 (cross-domain chains, EC, customer order, order-master outstanding, phase 1/2 regression all traced); test-level fit 10% → 7 (pyramid deviation, justified below); repository evidence 10% → 8 (codebase-memory graph + disclosed text-search fallback for `ldx_ec`).
- Total test cases: 101 finalized + 0 PENDING.

## 2. Data Preparation Summary

- **Core slips per domain** (graph-resolved models): `stock.picking` (Arrival/Shipment Slip record) `transfer_type='arrival'` and `'shipment'` in `state` `draft` (Waiting) and `done` (Confirmed); `store.sales` (Store Sales/Store Sales Return record) `sales_operation_type` `'sales'` (STS-) and `'return'` (RSTS-) in `draft`/`done`. Variants: clean Confirmed, already 取消待ち, already 取消確定, closing-locked (date before a closed period via `change.lock.date.history` — period-closing history, 締め).
- **Arrival link fixtures**: linked Purchase `account.move` (Purchase Slip record) in Draft / Confirmed+Not Paid / Confirmed+Paid (payment status set via reconciled payment); Order `order.master` (Order Slip record) Confirmed with arrival created; inter-store movement pair (`inter.store.movement`, 店舗間移動 → shipment done + arrival done, and shipment done + arrival draft).
- **Shipment link fixtures**: Sales `sale.order` (Sales Slip record) Draft; Confirmed with billing Draft; Confirmed with billing Confirmed (blocker); linked arrival Waiting (draft) and Confirmed (blocker); Customer Order `receipt.order` (Customer Order Slip record) Confirmed.
- **Store Sales link fixtures**: store-sales-return (RSTS) Draft and Confirmed linked via `return_store_slip_id`; `ec.order.receive` (EC Customer Order) Confirmed pointing `store_sales_id`; Sales `sale.order` (Sales Slip record) Confirmed without and with a Sales Return (`warehouse.return.instruction` — Sales Return Slip record — Confirmed).
- **Store Sales Return link fixtures**: `ec.order.return` (EC Customer Order Return) Confirmed pointing at the RSTS slip; `warehouse.return.instruction` (Sales Return Slip record) Confirmed linked via `store_sales_return_id`; original STS slip Confirmed.
- **Inventory/lot/outstanding baselines**: product with free/reserved/total quantities captured before cancel; a lot created by the target arrival and consumed nowhere; a lot shared with another consumer (negative case); `order.master` (Order Slip record) outstanding quantity captured before arrival cancel.
- **Actors**: users with authority levels Read / Write / Approve / Write+Approve for each of the four new items; a guest user with none.
- **Upload files per domain**: valid rows (New + Update on pending), and single-error variants — blank slip no, unknown no, already-cancelled no, duplicate no, invalid reason, reason `Others` with blank details, mixed valid+invalid (rollback), large file (volume), JP-locale headers 新規/更新 and EN New/Update.
- **Selection sets for batch**: empty, one, many; mixed Confirmed+Pending; mixed STS+RSTS; includes a 取消確定 slip (error).
- **Locale/timezone**: JP and EN sessions; a slip cancelled near midnight UTC to render `cancellation_date` (取消日時) in JST.
- **Reset/cleanup**: synthetic data only; cancellation markers and created slips removed per suite teardown; no shared-environment mutations.
